## 배운 것
- 단방향 데이터 흐름. 상태는 App에만, 아래는 콜백으로 보고, 보고서는 올라가며 id가 채워진다.
- 함수는 값. props로 넘기면 같은 함수에 이름표 추가. 화살표로 감싸면 새 함수.
- 포장지 패턴 두 종류: onClick에 인자 넣기, 위에서 온 함수에 내 정보 끼우기.
- 불변 업데이트 3종: 삭제 filter, 추가 [...arr, x], 수정 map + spread.
- 제어 컴포넌트 = value + onChange 세트, 단일 진실 원천.
- 이벤트 버블링. 부모 onClick + 자식 input = 의심.
- setState는 줄 세우기. 함수형은 최신 상태를 읽는 레시피.
- 콜백 시그니처 원칙: 말단은 모르는 정보 요구 안 받음 / id는 map 도는 곳에서 / 중간층은 통과.

## 어려웠던 것
- "상태 만들었는데 다음에 뭐 하지" → 한 기능을 끝까지 뚫기.
- 콜백을 데이터 안에서 찾음(`board.onDeleteCard`).
- `onClick={onDelete}`에 이벤트가 들어감.
- `(title) => onAddCard(column.id, title)`가 뭘 하는지 전혀 감이 안 옴 → 봉투/보고서 비유로 풀림. 이 단계에서 가장 오래 걸린 개념.
- `!!` 조건 반전, div 버블링, filter+append로 순서 깨짐.
- "Column이 어떻게 card.id를 아나" → map 매개변수. "App에서 다 잡으면 안 되나" → App은 어느 카드가 눌렸는지 모름.

## 면접에서 말할 것

- "제어 컴포넌트는 React 상태가 단일 진실 원천이고, 리렌더 범위를 줄이려 폼을 분리했습니다."
- "하위 컴포넌트는 콜백으로 이벤트만 올리고, 각 층이 아는 id를 끼워 올립니다. 중간층은 통과시켜 불필요한 함수 생성을 줄였습니다."
- "새 상태가 이전 상태에 의존하면 함수형 setter를 씁니다."
