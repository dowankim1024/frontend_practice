## 배운 것
- 옵셔널(`?`)은 "비어 있을 수 있음"이 아니라 "없을 수 있음". 컬렉션은 빈 배열로 표현하고 필수로 둔다.
- 도메인 타입(`type.ts`)과 props 타입(컴포넌트 파일 안)은 다른 개념. props에는 콜백처럼 데이터가 아닌 것도 들어간다.
- TS 에러는 타입 이름과 속성 이름을 찾아 `type.ts`와 대조하면 거의 답이 나온다.
- 타입을 먼저 붙이면 데이터 모양이 틀렸을 때 컴파일러가 잡아준다는 걸 `initialBoard: Board`에서 체감.
- key는 `map`이 반환하는 요소에, 안정적인 id로.
- flex 방향은 자식이 아니라 부모 컨테이너에 쓴다.

## 어려웠던 것
- 타입 파일에서 "무엇을 담을지"부터 막힘 → 화면에 필요한 것만 거꾸로 적기.
- `Board`의 역할이 뭔지 모호 → 4·6단계에서 상태 루트가 될 자리.
- props 타입을 만들라는 말에 도메인 타입 이름을 전부 `XxxProps`로 바꿈. 매개변수 구조분해 `{ props }`의 의미를 오해. → Claude가 `Card.tsx` 직접 수정.
- CSS 정렬 방향을 어디에 쓰는지 모름 → Claude가 `Column`/`Board` CSS 작성.

## 면접에서 말할 것
- "옵셔널은 값이 비어 있을 때가 아니라 필드가 없을 수 있을 때만 씁니다. 배열은 빈 배열이 없음을 표현하니 필수로 둡니다."
- "props 타입은 컴포넌트의 입력 계약이라 도메인 타입과 분리했고, 그 컴포넌트만 쓰니까 파일 안에 뒀습니다."
- "index를 key로 쓰면 key가 자리에 붙어서 삭제·정렬 시 로컬 상태가 엉뚱한 항목에 남습니다."
