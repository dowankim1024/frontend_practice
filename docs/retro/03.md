# Stage 3 회고 — useReducer + Context

- 2026-10-01, 하루.

## 배운 것
- 리듀서 = "이전 상태 + 액션 → 다음 상태" 순수 함수. React 없이 Node에서 호출해보니 그냥 함수였다.
- useReducer = useState인데 새 값 대신 액션을 넣고 리듀서가 계산해주는 버전.
- Context = props 안 거치는 배달 통로. 상태 관리 아님. 전역 아님(Provider 서브트리). 상태는 Provider의 useReducer에 산다.
- 상태/dispatch Context 분리 이유는 리렌더 범위.
- discriminated union + never로 case 누락을 컴파일 타임에.
- 리듀서 순수성: 랜덤 id는 dispatch 쪽에서 만들어 payload로.
- Fast Refresh 때문에 컴포넌트/훅/Context 객체는 파일 분리.

## 어려웠던 것
- 리듀서·Context가 뭔지 개념 자체. 틀을 받아서 몸통만 옮기는 방식으로 통과.
- useReducer가 뭔 뜻인지 → useState와 나란히 비교표.
- "되긴 하는데 감이 안 온다" → Node에서 직접 호출해서 출력 보기.
- App의 빨간 줄을 어디서 가져와 푸나 → App이 안 넘기면 풀린다.
- 면접 Q2(분리 이유), Q5(never)는 답 못 함.

## 면접에서 말할 것
- "여러 액션이 같은 상태를 건드리고 다음 상태가 이전 상태에 의존해서 useReducer로 옮겼고, 리듀서를 순수하게 유지해 테스트 가능하게 했습니다."
- "Context는 저장소가 아니라 의존성 주입 도구입니다. 상태와 dispatch를 분리해 dispatch만 쓰는 컴포넌트가 불필요하게 리렌더되지 않게 했습니다."
- "액션 타입은 discriminated union이고 default에서 never로 exhaustive check를 걸어 액션 추가 시 리듀서 누락을 컴파일 타임에 잡습니다."
