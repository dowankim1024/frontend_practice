# key

## 한 줄 정의
배열로 그린 형제 요소들 사이에서 "너는 누구냐"를 React에게 알려주는 식별자. 리렌더 시 이전 요소와 새 요소를 짝짓는 데 쓴다.

## 어디에 붙이나
`map`이 **반환하는 요소**에. 컴포넌트 안쪽 `div`에 붙이면 배열 밖이라 React가 못 본다.
```tsx
{cards.map((card) => <Card key={card.id} card={card} />)}
```

## key는 props가 아니다
`key={...}`라고 써도 컴포넌트 안에서 `props.key`로 못 꺼낸다. React가 가로채는 특수 속성. `CardProps`에 넣을 필요 없음.

## index를 key로 쓰면
key가 항목이 아니라 **자리**에 붙는다.
- `[A, B, C]`에서 A 삭제 → `[B, C]`. B가 index 0이 됨.
- React: "index 0은 그대로 있고 내용만 A→B로 바뀌었네."
- 결과 1: A 자리에 있던 로컬 상태(입력 중이던 텍스트, 체크 상태, 포커스)가 B에 남는다.
- 결과 2: 실제로는 A 하나 지웠는데 React는 B, C 전부 "변경됨"으로 보고 다시 그린다.

### "리렌더가 안 되는 것" 아님. "잘못된 짝으로 리렌더되는 것"
카드 A, B, C. 각 카드 안에 `useState`로 편집 중 텍스트가 있다. A의 input에 "hello" 치다가 A 삭제.

| key | 이전 | 이후 | React 판단 |
|-----|------|------|-----------|
| 0 | A | B | 같은 컴포넌트, props만 바뀜 → **인스턴스 유지**, 제목만 갱신 |
| 1 | B | C | 위와 같음 |
| 2 | C | — | 사라짐 → 언마운트 |

0번 인스턴스(원래 A)가 살아남아 B 옷을 입는다. 화면엔 B 제목, input엔 A에 치던 "hello". 실제 삭제는 1개인데 React는 2개를 다시 그린다.
id key면 "A가 사라졌다"를 정확히 알고 A 인스턴스만 언마운트, B·C 상태는 따라간다.

1단계는 카드에 내부 상태가 없어 티가 안 남. 2단계에서 편집 input이 생기는 순간 실제 버그가 된다.

순서가 절대 안 바뀌고 추가/삭제도 없는 정적 목록에서만 index가 안전하다. 칸반은 5단계에서 순서가 바뀌므로 반드시 id.

## `&&` 조건부 렌더링 함정
```tsx
{count && <p>{count}</p>}   // count가 0이면 화면에 "0"이 찍힌다
```
`&&`는 왼쪽이 falsy면 왼쪽 값을 그대로 반환. React는 `false`, `null`, `undefined`는 안 그리지만 `0`과 `""`은... `0`은 그린다(`""`는 안 보임).
해결: `count > 0 && ...`, `!!count && ...`, 또는 삼항.
이 프로젝트의 `card.description && ...`은 문자열이라 안전.

## 면접에서 이렇게 말한다
> "key는 배열 렌더링에서 React가 이전 요소와 새 요소를 짝짓는 식별자입니다. index를 쓰면 key가 항목이 아니라 자리에 붙어서, 삭제나 정렬 시 로컬 상태가 엉뚱한 항목에 남고 불필요한 리렌더가 생깁니다. 그래서 안정적인 id를 씁니다. key는 props로 전달되지 않는 특수 속성이라는 점도 알고 있습니다."
